# Verification documents

Use this when a professional, supplier or courier asks why verification is
pending, what to upload, or how to fix a rejection.

## What verification is

4Ceria checks identity and practice documents before a professional or
supplier can operate fully. Statuses are `pending` → `verified`, or
`rejected` with a reason. Verification history is kept for audit, so a
rejected upload should be corrected, not hidden.

## Role checklists

| Role | Core documents |
|---|---|
| arsitek | KTP, selfie, practice licence/STRA if held, portfolio, education |
| kontraktor | KTP, selfie, company deed/NIB, SIUJK/SBU if held, portfolio |
| interior | KTP, selfie, company/NIB if trading as a firm, portfolio |
| notaris | KTP, selfie, notary decree (SK), working-area letter, office address |
| project_manager | KTP, selfie, CV/portfolio, relevant certification |
| structural | KTP, selfie, engineering licence/STRI if held, portfolio |
| mep | KTP, selfie, engineering licence if held, portfolio |
| supplier | KTP/owner ID, company deed/NIB, storefront/warehouse evidence |
| courier | KTP, selfie, vehicle and licence (SIM) evidence |

Requirements can differ by role and by what the document is meant to prove.
The authoritative list is the upload screen for that role; use it rather than
guessing. Never tell a user to forge, alter or borrow a document.

## Fixing a rejection

1. Read the rejection reason and identify the exact document.
2. Re-upload a clear, complete, current copy.
3. Match the name and number to the account profile.
4. If the reason is unclear, ask support to restate it; do not resubmit the
   same file unchanged.

## Output

Use `references/documents.md`. List only the missing or rejected items, then
one next action per item.
